# 接手旧项目启动词

适用于自己的旧项目、别人写好的项目或 clone 后第一次开始改。没有任务 ID 时写本次目标即可，不要求先整理全仓。

```text
请接手这个项目。
项目位置或来源：[本地目录 / 仓库地址]
本次目标或任务：[想得到什么 / Backlog Task ID]

使用我的 Owner 工作方式：
https://github.com/shira-qwq/owner-workflow-kit
先检查 owner-project-control 和 owner-plain-language-zh 是否已安装；缺失时按 README 安装到宿主实际读取的技能目录。工具包放独立工具目录，别混入业务源码，已有副本不要无故重复下载。

先读现有项目规则、当前 handoff、当前任务及它直接引用的意图和证据，再核对相关 Git 和执行者状态。保护已有未提交修改、有效研究、数据缓存和检查点。不要无目的全仓考古、重新研究未变内容或运行未授权的数据生产。

复用已有任务和文档体系；Backlog 作为唯一任务系统，有其他正式任务系统时先说明迁移差异，不创建两个并行真相。打开并核对正确项目的 Backlog Web UI，补一个足够短的新 Agent 入口。

先分清原项目已有能力与我本次批准的目标。我的新想法先判断是否改变范围；新增能力优先查成熟方案，必要时先有界研究。研究与中间结果写入持久记录；只需我决定真正的产品取舍、风险或显著投入变化。

允许你安全整理外层目录与散落产物：先给旧→新映射、检查入口和依赖、建立保存点，再按小批迁移并验证。不因好看搬动包内部文件、数据库或构建路径，不同时开展大规模整理与功能扩张。优先复用已有文件说明、数据地图或 atlas，必要时用 Archify 生成带稳定名称和证据的局部阅读图，不恢复旧主控。

如需远端同步，使用我自己有权使用的仓库；原作者 origin 不自动当我的备份目标，保留来源和许可证。不能 force push、丢弃未知修改或偷偷混入其他工作。

核对是否可以直接接手；可继续就完成已授权工作。结束或暂停时更新任务、证据和短交接，主动保存合理版本；说明完成效果、未验证部分和下一步。
```
