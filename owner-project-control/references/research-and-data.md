# 研究与数据工作规则

仅在研究、模型 / Prompt 试验、数据生产清洗、批量转换或长任务时读取。执行方法仍由 Agent 和项目已有工具决定；不要求安装数据平台或新增数据 Skill。

## 先划定研究与运行边界

- 当前 Backlog Task 说明问题 / 假设、输入与允许改动的产物、完成条件。可行性讨论不等于生产化授权；研究 Task 可以交付“不可行”或“证据不足”，研究工作是否完成与产品假设是否成立分别报告。
- 不确定方案先做能回答问题的有界 research / spike / prototype；验证不成立时收束结论，不自行搭完整产品。已有明确研究范围就执行，不为常规技术选择逐个问 Owner。
- 长期结论写入已有 research / docs / decision / Skill；原始来源、分析推断、最终结论可在同一小文档分节。数据或日志大的才分文件，报告引用它们，不制作日常冻结包。
- 研究未完成也可保存：当前问题、已查来源 / 版本、已证实与未证实结论、被否定方向及条件、现有样本 / 产物、下一项能区分假设的检查。写在原研究记录或 Task 链接，handoff 只给入口。不为中间状态新增正式状态系统。
- 失败记录按适用条件保留：同输入、版本和配置下已失败的方向不要盲试；条件改变允许重新评估并写明原因。当前问题解决后，从 rolling handoff 删除过期失败说明，长期有用结论留原研究或决定，不永久污染每轮上下文。

## 先小样本，再扩大

1. 从任务引用和数据说明确认输入位置、版本、读取方式、目标输出与数量依据，不因接手而递归扫大型数据根。有缓存、投影和检查点时先核对兼容性。
2. 极小 smoke test 先验证读取、schema、写出与基本语义，再选覆盖主要类别、长短输入、缺失及异常边界的代表样本。样本数取决于多样性、风险和成本，不固定；文件前几行不能自动视为代表样本。
3. 检查输出结构与内容质量，并在目标配置下测吞吐、失败 / 重试情况、资源或费用。提示词、输入方式、并发和模型有实质变化时，重做受影响的小样本验证。
4. 在已授权全量范围与投入内，样本质量达到已约定标准即可自行扩大；只授权研究 / 样本、风格需要 Owner 判断、预计投入明显超出边界或出现质量问题时，暂停相关扩大并说明原因。每一阶段不默认需要人工批准。
5. 全量结束检查实际成功、失败、跳过、重复与预期总数的关系；抽样结论注明覆盖范围，不能把样本 PASS 当全量语义正确。

## 进度与实测 ETA

- 无实测数据时说“尚不能可靠估计，先测样本”；若必须给粗估，明确依据和不确定区间。
- 记录 processed / total（含计数口径）、成功 / 失败、elapsed、rate。使用同配置的实测有效吞吐估计剩余时间：remaining / measured rate，并加上独立的收尾验证时间。总数未知时不编造百分比或完成时刻。
- 分清本次执行与累计完成，重试不算新增完成；并发吞吐用实际完成数 / 墙钟时间，不能再乘并发数。异质任务按类别或阶段估计，明显变慢时更新 ETA。
- 实测估计也不是承诺；说明是否包含排队、限流、重试、启动和收尾。样本太短或太容易时给区间，说明代表性不足。
- 已有工具支持进度条或日志就复用。聊天能汇报时给简短更新；会话结束后不能持续观察就如实说明，提供进度文件与恢复入口，不承诺未配置的后台通知。

## checkpoint / resume

- 先复用现有运行器的断点和缓存；否则长任务按独立块持久保存输出与完成记录，避免最后一次才写盘。
- 最小运行记录包含输入身份 / 版本、处理代码与配置版本（AI 任务含模型与 Prompt 标识）、输出位置、已完成块或 ID、失败项、恢复命令。优先机器可读，handoff 只引用该记录和下一恢复动作，不复制逐项进度。
- 输出完整写入并验证后才标记块完成；临时结果不能冒充成功。恢复先核对输入和配置兼容以及输出确实存在，只重做缺失或失效块，不因换 Agent 全部重算。
- 有必要的长任务在小样本阶段验证一次“中断后恢复”和重复运行：不漏项、不重复追加、不混入不同配置结果。无需声称模型输出逐字确定；缓存保留已经验证的结果。
- 外部写入有副作用时使用目标支持的去重键 / 幂等机制；结果不明时先核对，不盲目重试。checkpoint 不是 Git commit，Git 回滚也不自动恢复数据库或外部副作用。

## 可复用处理与数据保护

- 同类处理会再次发生、需恢复或人工步骤易错时，优先复用已有脚本；没有再形成参数明确的脚本。一次性简单操作不搭框架。
- 输入、输出与关键参数明确，适用时支持 sample / limit、dry-run 与 resume。dry-run 应明确是否只预览还是仍有付费读取，不能名为预览却写正式产物。
- 原始数据默认不覆盖；canonical（权威数据）、generated（生成结果）、derived（派生数据）的角色与位置按项目已有习惯说明，不强制搬目录。
- 重要数据留最小来源记录：来自哪里、输入版本或标识、转换脚本 / 参数、输出版本与位置、数量与质量状态。一次验证计算可复用的统计，避免每轮重新扫描或重新哈希全部数据。
- 检查实际数量及任务相关的 ID / key 唯一性、必填字段、schema、关联完整性；另查语义和异常分布。程序退出成功只是运行成功，不能代替数据正确。
- Builder / production transform 仅在当前任务授权覆盖其目标与副作用时运行。输入保护、事务或备份策略根据真实风险选择，不把所有工作都变成审批。

## 分工与来源

### 按需功能与数据地图

- 已有 registry / lineage / atlas / 架构图时复用，不从零建第二份事实表。Owner 想知道“影响哪个功能”时，从用户能力出发，只展开相关数据来源、处理与结果；任务依赖箭头和数据流箭头不得混用。
- 节点沿用已有稳定 ID 与中文名；没有才在图源给局部稳定 ID。保留图源和可重建的阅读 HTML，任务链接到它们。地图不存第二份任务状态，不为所有项目强建资产目录。
- 图或其已有说明索引关联：节点 ID / 名称、功能用途、来源文件或数据标识、相关任务 / evidence、依据版本和确认范围。未知关系明确未知，推测关系不可画成已证实的运行链。渲染校验通过只证明图结构合规，不证明程序或数据真实如此运行。
- Owner 可以说“修改节点 X 的某项功能”；Agent 先核对地图版本与 X 的当前实现、任务和批准意图，再确定改动。名字只是定位入口，不授权执行所有下游；图上的可达路径也不等于已证实的故障影响范围。
- Archify 可用于搜索、聚焦和追踪已写入图源的关系；不把它当节点式运行器。正式项目有已有 atlas 时继续用它，Archify 只作按需局部解释。具体链接能力按安装版本验证，不虚构节点能直接打开任意证据。
- 只在相关结构、来源或功能边界变化时刷新受影响图；不因换窗口重画，不为了刷新地图重跑数据 Builder。过期图保留“对应哪个版本”提示，不能假装实时监控。

本文件只设通用底线。项目 AGENTS 放少量入口和特殊禁区；数据说明保管位置与来源；脚本 / 运行器实现恢复与校验；Backlog 存完成条件、运行记录链接和摘要。Superpowers 继续负责调试和验证方法。

- [Airflow best practices](https://airflow.apache.org/docs/apache-airflow/stable/best-practices.html)：参考重试一致性、固定输入分区、避免半成品输出；不采用 Airflow 平台本身。
- [Nextflow 官方恢复教程](https://training.nextflow.io/latest/nextflow_run/01_basics/)：参考复用仍有效的缓存结果；不要求安装 Nextflow。
- [nf-core 小测试配置示例](https://training.nextflow.io/latest/nf4_science/imaging/04_config/)：参考测试输入与正式运行分离；代表样本和 Owner 风格判断是本场景补充。
- [tqdm 文档](https://tqdm.github.io/docs/tqdm/)：可复用其进度、elapsed、rate 等展示能力；ETA 的口径和扩大条件由本任务确定。
